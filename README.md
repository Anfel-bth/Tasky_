# Tasky

Tasky is a React/Vite task manager backed by an Express API and PostgreSQL. This repository includes a Render Blueprint in `render.yaml` for deploying the frontend, API, and database together.

## Local setup

1. Copy `task-manager-backend/.env.example` to `task-manager-backend/.env`, then set the PostgreSQL and email values.
2. Copy `task-manager-frontend/.env.example` to `task-manager-frontend/.env`.
3. Install dependencies in each project directory with `npm ci`.
4. Start the API with `npm run dev` from `task-manager-backend`.
5. Start Vite with `npm run dev` from `task-manager-frontend`.

The API initializes the database tables and built-in categories before it starts listening. Locally, Vite forwards `/api` requests to `http://localhost:5000`.

## Render deployment

1. Push the repository to a Git provider connected to Render.
2. In Render, create a new Blueprint and select this repository. Render reads `render.yaml` at the repository root. Review the resources and select a region.
3. Set the `RESEND_API_KEY` and `EMAIL_FROM` values requested for the API service. The sender address must be on a domain verified with Resend.
4. Once services have been created, verify the API and frontend URLs. If Render assigns different hostnames, update `CORS_ORIGIN` on `tasky-api` and `VITE_API_BASE` on `tasky-frontend`; redeploy the API and rebuild the frontend.
5. Check the API service logs and visit `/api/test-db` on its URL to verify database connectivity.

`VITE_API_BASE` is embedded in the frontend at build time. Changing it requires a frontend redeploy. `JWT_SECRET` is generated by the Blueprint; do not replace it with a checked-in value. The database connection string is supplied by Render and should remain a secret.

The Blueprint currently selects Render's free PostgreSQL plan to avoid creating a paid resource by default. Render free databases are temporary and unsuitable for persistent production data; choose a paid database plan before relying on Tasky for important data. Free web services may also sleep when idle.

## OTP email delivery

Tasky can send OTP email through either Resend's HTTPS API or a configurable SMTP server. Resend is the default deployment configuration because some hosts restrict outbound SMTP. Configure a valid Resend API key and verified sender before using registration. If the hosting platform blocks outbound HTTPS as well, use a transactional email provider/API supported by that platform; OTP delivery cannot work without an available outbound email channel.

For SMTP, set `EMAIL_PROVIDER=smtp`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_SECURE`, `EMAIL_FROM`, and any required `EMAIL_USER`/`EMAIL_PASS` credentials. SMTP may still fail if the host blocks that port.
